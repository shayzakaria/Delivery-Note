# ניתוח המערכת — דיווח משלוחים וחשבוניות לפורטל שיכון ובינוי / סולל בונה

מסמך זה מסכם את ניתוח חומרי המקור (מדריך העבודה, מדריך דוח R4820SB, שני קבצי Excel לדוגמה וקוד האפליקציה המקורית),
את הלוגיקה העסקית כפי שמומשה מחדש, את התקלות שנמצאו במקור ואת השאלות שנותרו פתוחות.

## 1. התהליך מקצה לקצה

```
ERP (וואן)                      פורטל הספקים (שו"ב)                האתר                         פורטל הספקים
────────────                    ────────────────────               ─────                        ────────────
דוח R4820SB  ──► shob_cp_pdf323.bat ──► תיקיית הסריקות ...\shob\323\S<תעודה>.pdf ─┐
                                "הזמנות פתוחות" ► Excel ─────────────► טעינה ► סימון פריטים ► ZIP ─► "קליטת משלוחים מקובץ"
                                                                        + תעודה + תאריך     (CSV+PDF)   (CSV → "0 שגיאות" → PDF → שלח)
דוח חשבוניות ► Excel ──────────┐
                                "סטטוס משלוחים" ► Excel ─► התאמת חשבוניות (מע"מ, עיגול) ► ZIP (CSV 12 עמודות + I<חשבונית>.pdf)
```

1. **סריקת תעודות (R4820SB):** הדוח מפיק שורות `copy /Y <סריקה מקורית>.pdf <תיקיית הסריקות>\shob\323\S<תעודה>.pdf`.
   שומרים אותו כקובץ BAT בשולחן העבודה ומריצים. התוצאה: תיקייה שבה כל תעודה היא `S` + מספר התעודה + `.pdf`.
2. **הזמנות פתוחות:** מורידים מהפורטל (טווח של עד 500 יום) את קובץ ה-Excel.
3. **באתר:** טוענים את הקובץ, מאתרים הזמנה (ספרות אחרונות / מספר דירה), מזינים מספר תעודה ותאריך, מסמנים פריטים וכמויות.
4. **סיכום וייצוא:** בוחרים את תיקיית 323. האתר מתאים PDF לכל תעודה (✓ ירוק / ○ אפור / ✗ אדום) ומוריד ZIP.
5. **בפורטל:** "קליטת משלוחים מקובץ" ← צרף קובץ (ה-CSV) ← לוודא "0 שגיאות" ← צרף קבצים (כל ה-PDF) ← שלח.
6. **חשבוניות:** בלשונית ⚖ טוענים את דוח "סטטוס משלוחים" מהפורטל ואת דוח החשבוניות מה-ERP. האתר מצליב לפי מספר תעודת משלוח ומפיק קובץ ממשק חשבוניות.

## 2. פורמטים

### 2.1 קובץ "הזמנות פתוחות" (קלט)
נקרא לפי מיקום עמודה, בדיוק כמו באפליקציה המקורית. **לא צורפה דוגמה של הקובץ** — ראו שאלות פתוחות.

| עמודה | שדה | הערות |
|---|---|---|
| A (0) | קוד אתר | מספר — נכתב לעמודה 1 ב-CSV |
| B (1) | שם אתר | לסינון/תצוגה |
| D (3) | תאריך הזמנה | תצוגה בלבד |
| E (4) | מספר הזמנה (PO) | |
| F (5) | פרטים (למשל "דירה 8") | חיפוש |
| G (6) | קניין | סינון |
| J (9) | מק"ט | |
| L (11) | תיאור פריט | |
| M (12) | כמות בהזמנה | |
| N (13) | כמות למשלוח (יתרה) | שורות עם 0 מסוננות |
| P (15) | מחיר יחידה | |
| R (17) | סה"כ שורה | |

**מספר שורת הזמנה** = מיקום השורה בתוך ההזמנה בקובץ, נספר **לפני** סינון שורות סגורות (כך "שורה 19 מתוך 24" נשארת 19).
שורה נספרת כשיש בה אתר (A) ומספר הזמנה (E).

### 2.2 קובץ קליטת משלוחים (פלט) — 9 עמודות, ללא כותרת, UTF-8 עם BOM, שורות מופרדות ב-LF
```
קוד אתר, מספר תעודה, DD/MM/YY, מק"ט, (מק"ט יצרן ריק), כמות, מחיר יחידה, מספר הזמנה, שורת הזמנה
10000074,700000001,01/08/26,5000000001,,1,40,PO202600000101,15
```
שם הקובץ `DD-MM-YYYY.csv` (תאריך הייצוא). החבילה: `DD-MM-YYYY_משלוחים.zip` ובתוכה תיקייה באותו שם עם ה-CSV וקבצי ה-PDF בשמם המקורי.

### 2.3 דוח "סטטוס משלוחים" מהפורטל (קלט, התאמת חשבוניות)
כותרות: אתר, חברה, תאריך, תעודה סולל, **תעודת ספק**, סטטוס, מקט, מקט יצרן, תאור, כמות ספק, **כמות שהתקבלה**, **מחיר יחידה**, מטבע, **סהכ מחיר**, הערה.
העמודות מזוהות לפי שם (שורת כותרת בתוך 25 השורות הראשונות, לפחות 60% מהשמות). הסכומים לפני מע"מ.

### 2.4 דוח חשבוניות מה-ERP (קלט)
כותרות: מספר כרטיס, שם כרטיס, קוד לקוח, שם לקוח, **מספר חשבונית**, **סכום חשבונית** (כולל מע"מ), **תאריך חשבונית**, **מספר הקצאה**, תקופת מאזן, תעודה פיננסית, **תעודת משלוח**, **הזמנת שו"ב**, **מס.פרוייקט שו"ב**, הערת פרטים 2.

### 2.5 קובץ ממשק חשבוניות (פלט) — 12 עמודות
```
אתר, מספר חשבונית, מספר הקצאה, D, DD/MM/YY, מק"ט, (מק"ט ספק ריק), כמות, מחיר יחידה, מספר תעודת משלוח, מספר הזמנה*, שורת הזמנה*
```
\* עמודות 11–12 מתמלאות רק כאשר אותו מק"ט מופיע באותה תעודה במחירים שונים (אחרת הפורטל יודע לשייך לבד).
שורות במחיר נמוך מ-₪1 אינן נכתבות (הפורטל אינו קולט שורות 0).
חבילה: `DD-MM-YYYY_חשבוניות.zip` ובה ה-CSV, קובץ שגויים (אם יש) וקבצי PDF בשם `I<מספר חשבונית>.pdf`.

## 3. כללי ההתאמה (⚖)

- הצלבה לפי מספר תעודת משלוח.
- **תקין:** |סכום החשבונית − (סכום התעודה בפורטל × (1 + מע"מ))| ≤ הפרש עיגול (ברירת מחדל 18% ו-₪1).
- **סכום שונה** / **לא נמצא** — אינם נכנסים לקובץ ומופיעים בקובץ השגויים.
- **מספר שורת הזמנה** נשלף מהיסטוריית דיווחי המשלוחים (אותה תעודה, אותו מק"ט **ואותו מחיר**, עדיפות לאותה כמות), או מוזן ידנית.

בדוגמה שצורפה (11 חשבוניות, 172 תעודות): 8 תקינות, 3 לא נמצאו בפורטל; חשבונית אחת דורשת מספרי שורה (אותו מק"ט בשני מחירים שונים).
התוצאה אומתה בשני מימושים בלתי תלויים (Python ו-TypeScript).

## 5. שאלות פתוחות (דורשות החלטה עסקית)

1. **כמות בחשבונית:** בדוח הפורטל יש שורות עם "כמות שהתקבלה" = 0 אך "סהכ מחיר" מלא (כ-20 שורות בדוגמה). האפליקציה המקורית כותבת לקובץ את הכמות שהתקבלה (0),
   אך מתאימה סכומים לפי "סהכ מחיר". כך בדוגמה חשבונית אחת מסומנת "תקינה" ויוצאת עם שורה בכמות 0. נשמרה ההתנהגות המקורית, עם אזהרה בולטת.
   האם הפורטל מצפה ל"כמות ספק" במקרה כזה?
2. **קובץ הזמנות פתוחות:** לא צורפה דוגמה. דרושה דוגמה כדי לאשר את מיקומי העמודות, ובעיקר שהקובץ כולל גם שורות סגורות ובסדר השורות של ההזמנה
   (שממנו נגזר "שורת הזמנה"). אם יש בקובץ עמודת מספר שורה מפורשת — עדיף להשתמש בה.
3. **לשונית 🧾 חשבוניות:** מפיקה קובץ במבנה של 9 עמודות (כמו משלוחים), בעוד שלשונית ⚖ מפיקה את ממשק החשבוניות ב-12 עמודות. האם הלשונית עדיין בשימוש?
4. **זיכויים:** עמודה 4 תמיד `D`. האם יש חשבוניות זיכוי שצריכות `C`?
5. **סטטוס בפורטל:** כל השורות בדוגמה "מאושר(סופית)". כרגע תעודה בסטטוס אחר מסומנת בתווית אזהרה בלבד — האם לחסום אותה?
6. **מספר הקצאה:** חסר ב-10 מתוך 11 חשבוניות בדוגמה. האם הפורטל מחייב אותו?

## 6. מודל הנתונים (Supabase)

| טבלה | תוכן | הרשאות |
|---|---|---|
| `app_members` | מיילים מורשים ותפקיד (admin/user) | קריאה: חברים; שינוי: מנהלים; לא ניתן להסיר את המנהל האחרון שיכול להתחבר |
| `po_imports`, `po_lines` | כל טעינה של קובץ הזמנות פתוחות (20 אחרונות נשמרות); האחרונה פעילה | חברים קוראים; כתיבה רק דרך `import_open_orders` |
| `drafts` | בחירות בעבודה, לכל משתמש ולכל הזמנה | בעלים בלבד |
| `export_batches` | כל ייצוא: סוג, שם קובץ, תוכן ה-CSV, סכום, קבצי PDF, משתמש, זמן | חברים קוראים; כתיבה רק דרך `record_export`; מנהלים מוחקים; אין עריכה |
| `export_doc_lines` | שורות תעודות/חשבוניות שדווחו — מקור מספרי השורה להתאמת חשבוניות | חברים קוראים; נכתבות רק יחד עם הייצוא שלהן |

פונקציות: `import_open_orders`, `record_export` (אטומיות, מאמתות את הנתונים בצד השרת), `delivery_history_for_docs`, `invoice_history_for`, `current_member_role`.
הפונקציות הכותבות רצות בהרשאות מוגבלות בסכמה פרטית שאינה חשופה ל-API; למשתמשים אין הרשאת הוספה/מחיקה ישירה לטבלאות ההיסטוריה וההזמנות.

## 7. בקרת איכות

- **בדיקות אוטומטיות:** 47 בדיקות יחידה (פורמטי קבצים, ניתוח Excel, התאמה, ZIP — כולל אימות ה-ZIP במימוש בלתי תלוי) ו-15 בדיקות דפדפן מקצה לקצה
  (טעינה, סימון, הורדת חבילה ובדיקת תוכנה בייט-בייט, שמירה אחרי רענון, היסטוריה, התאמת חשבוניות, משתמשים והרשאות). רצות ב-GitHub Actions בכל דחיפה.
- **בדיקות אבטחה בבסיס הנתונים:** התחזות לאנונימי / משתמש לא מורשה / מייל לא מאומת / חבר / מנהל, בטרנזקציה שמתבטלת — כולל ניסיונות זיוף שורות היסטוריה.
- **סקירה אדוורסרית:** שישה סוקרים עצמאיים (התאמה למקור, אבטחה, מצב React, קלטים קיצוניים, התאמה למדריך) ומבקר ספקן לכל ממצא.
  23 ממצאים אומתו ותוקנו, בהם:
  - כשל רשת בטעינת ההזמנות היה עלול למחוק את הבחירות השמורות — תוקן, עם בדיקת רגרסיה שנכשלת ללא התיקון.
  - חבר יכול היה להוסיף שורות מזויפות לייצוא של משתמש אחר דרך ה-API — נחסם בצד השרת.
  - שמירה ממתינה בעת התנתקות יכלה להיכתב לחשבון המשתמש הבא באותו דפדפן — נחסם, והשינויים נשמרים לפני ההתנתקות.
  - מספר שורת הזמנה נלקח מהייצוא הישן ביותר של תעודה ולא מהאחרון — תוקן.
  - "1,200" נקרא כ-1.2; מספר תעודה עם S בתחילתו נשלח לפורטל כמו שהוא — תוקנו.
